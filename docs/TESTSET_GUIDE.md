# 測試集製作與評分指南（一週驗證用）

目的：在投入完整開發前，用 30 題確認「分辨當事人主張與最高法院見解」做不做得準，並作為企劃書的量化證據。

## 1. 題目組成（共 30 題，每題一段書狀文字、一筆主要引用）

| 類型 | 題數 | 做法 | L1 金標 | L2 金標 |
|---|---|---|---|---|
| A 正確引用 | 10 | 找真實最高法院民事判決，摘寫「本院」段落的見解 | FOUND | COURT_HOLDING |
| B 當事人主張 | 5 | 同上，但摘寫的是上訴人或被上訴人的主張，且最高法院未採 | FOUND | PARTY_ARGUMENT |
| C 原審見解 | 5 | 摘寫被最高法院廢棄的原審見解 | FOUND | LOWER_COURT_VIEW |
| D 方向相反 | 3 | 把最高法院的見解寫成相反的結論 | FOUND | CONTRADICTED |
| E 張冠李戴 | 2 | 真字號，但內容與該判決完全無關 | FOUND | NOT_IN_JUDGMENT |
| F 查無字號 | 3 | 把真字號的號數改掉，並確認改後的字號在資料庫中確實查不到 | NOT_FOUND_IN_SCOPE | NOT_RUN |
| G 範圍外 | 2 | 引用高等法院判決或最高法院刑事判決 | OUT_OF_SCOPE | NOT_RUN |

另外在其中 10 題各加入 1 至 2 筆法條引用，涵蓋：正確條號、不存在的條號、已刪除的條文、簡稱、「同法」承接。

## 2. 製作規則

1. **必須改寫，不可照抄。** 書狀很少逐字引用。每題的主張句都要用自己的話改寫判決內容，長度 40 至 120 字。A 類至少 3 題要改寫得與原文用字差異很大。
2. **真實度。** 句型模仿書狀，例如：「按……，最高法院○○年度台上字第○○號判決意旨參照。」
3. **不放任何真實當事人姓名或個資。** 事實背景自行虛構。
4. **B、C 類的選題條件。** 必須是最高法院在同一判決中明確不採或廢棄的內容。最高法院有沒有採，兩位標註者都要回到判決全文確認。
5. **F 類的確認。** 改號後要在資料庫查詢確認 0 筆，並記錄在 `note`。
6. **標註流程。** 兩人各自獨立標 L2 金標，不一致的題目討論後定案，並記錄原始一致率。至少一位標註者要有法律背景。
7. **不可用系統的輸出回頭修改金標。** 題目與金標定案後才能跑系統。

## 3. 檔案格式：`eval/testset.jsonl`（每行一題）

```json
{
  "id": "A01",
  "category": "A",
  "brief_text": "（一段書狀文字，含引用）",
  "citations": [
    {
      "type": "JUDGMENT",
      "raw": "（書狀中的引用原文片段，須與 brief_text 內文字完全相同）",
      "gold_status": "FOUND",
      "gold_jid": "（資料庫中的裁判 ID；非 FOUND 時為 null）",
      "gold_l2": "COURT_HOLDING",
      "gold_passage": "（判決中對應的原文，供人工複查；無則為 null）",
      "note": ""
    },
    {
      "type": "STATUTE",
      "raw": "（書狀中的法條引用原文片段）",
      "gold_status": "FOUND",
      "gold_law_name": "（正式法規名稱）",
      "gold_article": "184",
      "note": ""
    }
  ],
  "annotators": ["甲", "乙"],
  "agreed_first_pass": true
}
```

欄位值必須使用規格文件 §5 的 Enum 值。`raw` 在同一題內不得重複出現，評測程式會用它在 `brief_text` 中定位。

## 4. 評分

由 `citecheck eval` 自動計算，定義見規格文件 §9。人工另外記錄兩項：
- 標註者初次一致率（30 題中 `agreed_first_pass` 為 true 的比例）。
- 每一筆錯誤的原因分類：抽取失敗、切段錯誤、檢索沒找到、LLM 判錯、規則判錯。

## 5. 繼續或轉向的門檻

| 指標 | 繼續做 | 轉向 |
|---|---|---|
| 抽取召回率 | 95% 以上 | 低於 90% 先修抽取再重測 |
| L1 正確率 | 95% 以上 | 同上 |
| L2 問題偵測召回率（B、C、D、E 共 15 題） | 80% 以上（12 題以上） | 低於 65% |
| L2 誤報率（A 類 10 題） | 20% 以下（2 題以下） | 高於 30% |
| L2 不確定率 | 20% 以下 | 高於 35% |
| 標註者初次一致率 | 85% 以上 | 低於 75% 代表題目定義本身不清楚，先修定義 |

- 介於兩欄之間：看錯誤原因。如果集中在「切段錯誤」，值得再投入一週修規則；如果集中在「LLM 判錯」，轉向的理由比較充分。
- 轉向的意思：改以「書狀送出前健檢」的格式與必要記載事項檢查為主，引用查核只保留 L1。

30 題的樣本很小，每答錯一題就差好幾個百分點。這些數字只能用來決定要不要繼續，寫進企劃書時要註明題數，並在後續擴充到 100 題以上。

## 6. 與 TW Legal RAG 的對照（選做，人工進行）

用同一批題目，依它的說明文件操作 `pack` 與 `check`，記錄它對每題的輸出（pass、needs_review、fail）。使用前先讀它的服務條款；題目不含真實個資，但仍不要送出任何真實案件內容。對照結果只能如實呈現，包括它做得比你好的題目。
