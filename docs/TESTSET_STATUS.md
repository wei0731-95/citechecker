# 測試集狀態（eval/testset.jsonl）

- 30 題：A 10、B 5、C 5、D 3、E 2、F 3、G 2；共 42 筆金標引用（30 筆判決、12 筆法條，分布在 11 題）。重新產生與驗證：`python eval/build_testset.py`。
- 製作方式：我（Claude）先讀完 11 份真實最高法院民事判決（114／115 年度台上字，主文為上訴駁回或廢棄發回）的理由全文，再用自己的話改寫成書狀句子；沒有使用真實當事人姓名。每題金標在**執行系統之前**就已定案，之後沒有依系統輸出修改。
- 自動驗證（build_testset.py）：每個 `raw` 在書狀中恰出現一次；每段 `gold_passage` 逐字存在於該判決全文；F 類改號後資料庫確實 0 筆；12 筆法條的金標狀態（FOUND／ARTICLE_NOT_FOUND／ARTICLE_DELETED）與資料庫一致。
- 不跑 API 的檢查（`eval --no-l2`）：抽取召回率 42/42、L1 正確率 42/42。

## 與 TESTSET_GUIDE 不符之處（重要）
1. **只有一位標註者，而且是 AI。** 指南要求兩人獨立標註、至少一位有法律背景、記錄初次一致率。`annotators` 填 `["Claude(AI)"]`，`agreed_first_pass` 為 null。**未經人工複核前，這份測試集的結果不能當作正式證據寫進企劃書。**
2. 題目來源只有 11 份判決（A 類同一份判決出現 2–3 次），題目多樣性不足；建議正式版擴充。
3. 11 題含法條（指南為 10 題）。

## 建議人工優先複核的題目
- B 類（5 題）：我只選了本院明確表示不採、或採相反見解的當事人主張；請確認「未被採納」成立。
- C 類（5 題）：原審見解在判決中是以「原審…」複述；請確認廢棄理由確實針對該見解。
- A 類中改寫差異大者（A01、A03、A07）。
- 已知切段限制可能使 C 類被判成 COURT_HOLDING（本院段落複述原審見解），那是系統問題，不代表金標有誤。

## 法律複核備註（2026-11-16，Claude 以法律顧問角色複核，已對照資料庫全文）
- 9 題加上 `review_note` 欄位（定義在 build_testset.py 的 `REVIEW_NOTES`）：A02、A10、C02、C03、E01、E02、F01、F02、F03。
- A02、A10 的 `gold_passage` 換成或補上本院的抽象見解（只供人工複查，不參與評分）。**所有 `gold_l2`、`gold_status`、`brief_text` 都沒有改。**
- 重點：C02、C03 的書狀命題被本院理由明確駁斥，同時符合 D 類；A10 書狀比判決說得更絕對；E02 命題本身有實體錯誤（勞退新制資遣費）。
- 這不是指南 §2.6 要求的獨立第二標註（同為 AI），`annotators`／`agreed_first_pass` 不變，仍需具法律背景的人工複核。

- 維持 §7.5 規則順序（本院 CONTRADICTS 先於原審／當事人 SUPPORTS）。本版 B、C 題因「最高法院明確不採」而被判為 CONTRADICTED，逐題標籤 17/25，問題偵測 15/15。
